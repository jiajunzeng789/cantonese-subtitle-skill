# 环境复用与故障恢复

环境准备先执行[runtime-setup.md](runtime-setup.md)的`setup_runtime.py`，它提供统一的安装顺序、候选检查、真实解码自检、日志和独占锁。以下规则用于解释结果和处理脚本未能解决的问题，不另起一套任意版本的安装流程。实际自动记录字段以脚本输出为准，下面是扩展记录约定。

## 先检查，再安装

1. 查当前工作目录 `.cantonese-subtitles/environment.local.json`、用户已提供的环境路径，以及此前明确记录的本机共享配置 `~/.config/cantonese-subtitles/environment.local.json`。共享配置不存在时不全盘搜索，也不假定开发者机器路径可用。用户没有提供素材时可以先检查环境，不将缺少素材报成安装失败。
2. 检查解释器、平台和版本，用所选解释器执行后续检查及脚本。使用解释器的 `-m pip`，避免激活环境与实际执行程序不一致。不修改系统Python，不替换仍可用的环境。
3. 分别验证需要的模块导入：Whisper需要 `faster_whisper`；Qwen需要 `qwen_asr`、`torch`，当前短样本脚本还需要 `faster_whisper` 的VAD；文字处理需要 `opencc`，字体测量需要 `PIL`。记录完整输出、退出码及所用解释器，`pip list`里有名称不等于导入通过。
4. 对本地模型检查索引、权重分片和配置，再分别实际加载。明确CPU/CUDA/MPS实际可用情况；Whisper不使用MPS，Qwen可按本机能力选择。导入成功不等于模型加载成功，缓存目录存在不等于文件完整。
5. 已完成过本机短音频验证，且依赖与模型版本未变时，复用验证记录并检查文件仍在；新环境先做短音频验证。每次新素材仍需检查开场、切口和疑似漏段。

没有可复用环境时，再在当前工作目录创建专用环境；已有环境缺少依赖时，只补缺少部分。不要在多个终端或Agent里同时安装同一个环境。准备阶段允许联网下载公开文件，离线任务不得隐式下载。

## 国内网络与下载源

- 优先复用已验证环境及安装器可验证的本地缓存；确需下载时，再考虑换源。不要为了换源重复安装已经可用的包。
- 用户处于国内网络或默认源连接较差时，先检查可信国内HTTPS镜像，例如清华大学TUNA的 `https://mirrors.tuna.tsinghua.edu.cn/pypi/web/simple`。核对当前镜像说明、可达性，以及目标版本和本机Python/架构对应的文件是否存在，再决定是否使用。不保证镜像必然更快。
- 使用所选解释器的 `-m pip`，仅为本次安装命令设置 `--index-url`；不要执行全局 `pip config set global.index-url`，不要同时混用多个不明确的索引，不关闭TLS验证或安全防护。遵守用户或组织明确指定的下载源。
- 镜像缺少指定版本、平台文件或不可达时，说明实际原因，按既有重试规则改查官方源或其他明确可信来源。不能静默更改依赖版本或下载不匹配的CUDA/平台包来凑齐安装。
- 先根据操作系统、处理器和所选后端确定依赖，再下载。以目标安装文件与日志为依据报告体积，不把其他平台的大包大小或整套依赖总量当作当前PyTorch大小。
- 切换下载源前检查已有后台任务的真实状态。正在正常下载或已接近完成时不立即打断重来；需要切换时先确认旧任务已结束，再启动新任务，保留缓存。是否可复用部分下载由安装器及校验结果决定，不承诺一定能断点续传。
- PyPI镜像用于Python依赖，不能自动加速Whisper/Qwen模型权重下载。模型文件继续按官方支持方式取得并记录模型仓库与快照；不将依赖镜像地址套用到模型地址，也不换模型冒充同一基准。

镜像用法依据：[清华大学TUNA官方PyPI说明](https://mirrors.tuna.tsinghua.edu.cn/help/pypi/)。

## 本机记录

在当前工作目录的 `.cantonese-subtitles/` 保存环境记录及日志。需要供其他工作目录复用时，可在用户个人配置目录保存相同环境信息；保留已有无关配置，不记录密钥，不提交这些文件到GitHub。

建议环境记录字段如下，实际结果由工具填写，不能照抄成成功状态：

```json
{
  "schema_version": 1,
  "python_executable": "本机实际路径",
  "python_version": "实际检测版本",
  "platform": "实际检测平台",
  "package_versions": {},
  "models": {},
  "checks": {
    "whisper_import": {"status": "pending"},
    "qwen_import": {"status": "pending"},
    "whisper_load": {"status": "pending"},
    "qwen_load": {"status": "pending"},
    "sample_inference": {"status": "pending"}
  }
}
```

模型条目记录仓库、快照/版本、本机路径、设备及检查时间；成功条目附日志位置。升级依赖、更换解释器或模型、改变运行权限后重新验证相关条目，不沿用失效的成功记录。

## 分步准备与可见日志

按基础工具 → Whisper依赖 → Qwen依赖执行，每步单独保存命令、开始/结束时间、退出码和日志。已有部分通过检查时跳过重复安装。模型依次加载以控制内存占用，不下载额外高性能后端来解决未诊断的问题。

保留安装正常输出，不仅使用静默参数。任务较长可后台执行，但记录任务ID或进程ID、环境路径和输出日志；定期查询真实状态。等候超时不等于子进程失败，工具返回成功也可能只表示后台启动成功，必须检查最终退出码和验证结果。无法查询时报告未知状态，不再启动一个相同安装。

某项约60秒没有新输出时检查进程是否仍在、日志/下载文件是否变化及退出状态。静默不等于卡死，不盲目终止正在安装的进程。无法判断时说明已等待多久、最后一条进展和下一项检查，避免只显示“正在读取输出”。

## 故障分类与处理

| 已有证据 | 可采取的处理 |
|---|---|
| 连接超时、下载中断等网络错误 | 保留缓存，核对网络与下载源后重试；不因网络失败更换识别服务 |
| 构建失败、缺模块、无兼容版本或版本冲突 | 根据首个有效错误定位具体包、解释器和平台，采用对应修复；不默认升级全部包，也不盲目套用关闭构建隔离等参数 |
| 明确的目录或操作权限错误 | 指明目标路径和被拒绝操作，采用获准位置和正常权限流程，不绕过执行环境限制 |
| 明确的防护拦截提示或相关事件记录 | 核对具体程序、文件、操作和时间，优先复用可用环境或采用正常受支持的安装方式；需要用户处理时再解释具体操作及影响 |
| 只有失败摘要或等待提示 | 标记“原因待确认”，读取日志与任务状态，不推断为安全拦截 |

`sox`安装失败不能单独证明系统缺少SoX程序、缺NumPy或被安全中心阻止。缓存清理或临时目录出现删除操作也不能单独证明拦截。不默认要求关闭整个安全防护、恢复未知隔离项或重启软件；没有核实的设置名称不要给出确定的菜单路径。

针对同一错误，有证据支持的修复后最多自动重试一次。再次失败则标记失败步骤及依赖它的等待步骤，保留缓存和已成功部分。后续新的日志揭示了不同原因时可以继续针对性处理，不反复执行原命令。

Whisper可用而Qwen失败时，可保存Whisper原始结果及完成其他独立检查；双模型交叉校准仍未完成。不能静默降级为单模型或云端识别后声称双模型任务成功。

## 中断与恢复

每次完成或失败后更新进度记录。用户说“继续”时，先确认素材、成片设置、环境记录及未结束的任务；输入或版本变化时只重做受影响步骤。检查产物实际存在且对应本次素材，不仅依赖历史勾选状态。避免覆盖已有字幕，按版本保存重跑结果。
