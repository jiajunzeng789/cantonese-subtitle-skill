# 成片画幅、单行断句和导出

## 优先级与探测

依次采用：用户明确的最终成片尺寸/剪辑工程画幅 → 用户给的横竖屏预设 → 原视频显示尺寸。用户提供裁剪后的新画幅时，旧源文件宽高不再决定断句。只有MP3不能自动推断视频尺寸；音频封面也不能当作成片画幅。

探测器使用FFprobe读取主视频流，跳过attached_pic，应用sample_aspect_ratio与旋转信息。显示宽高比≥1.2先归横屏，≤0.85归竖屏，中间为方形/近方形。这些是预设选择的工程规则，不是平台发布标准。

```sh
# 根据视频显示尺寸选择预设
python scripts/subtitle_profile.py --media /absolute/source.mp4 --output /absolute/profile.json
# 原视频横屏但最终裁成竖屏，明确覆盖成片尺寸
python scripts/subtitle_profile.py --media /absolute/source.mp4 --final-size 1080x1920 --output /absolute/portrait.json
# 只有音频，使用已确认的成片类型
python scripts/subtitle_profile.py --media /absolute/audio.mp3 --layout landscape --output /absolute/landscape.json
```

未知音频画幅时，不默认假称“已检测横屏”；先问一次最终横屏还是竖屏。用户要两版时独立分句和定位，不用把横屏字幕的字号缩小就冒充竖屏版。

## 默认长度与字体

| 预设layout | 建议中文宽度单位 | 导出上限max_width |
|---|---|---|
| landscape 横屏 | 16～20 | 20 |
| portrait 竖屏 | 10～14 | 14 |
| square 方屏 | 12～16 | 16 |

一个汉字通常计1，ASCII字母、数字、半角空格各约0.5。读速初值不超过约9宽度单位/秒。这里的空格占宽度，不能为了绕过长度限制插入空格。宽度上限是可配置的初值，字体实际大小比单纯的屏幕比例更重要。

团队可在profile中增加：display_width/display_height、font_file（本地字体路径）、font_size_px、safe_width_fraction（默认0.8，即两侧合计约20%留白）、letter_spacing_px、stroke_width_px。提供字体和尺寸时，导出器用Pillow测量实际字体宽度，并同时检查预设上限和安全区宽度；需要可选依赖 `Pillow`。未提供字体时只做近似估计，不保证剪辑软件不会自动换行。仅提供字号时可按显示宽度估计可容纳的汉字数量，再与预设上限取较小值。

字体、字号、字距、描边及安全区应与剪辑软件实际设置相同。SRT不可靠承载这些布局参数；即使文本没有换行，软件仍可能自动折行。默认交付SRT时只检查正文单行及已知字体宽度，说明剪辑软件样式的局限即可，不渲染预览视频、不抽帧。只有用户明确要求画面预览或烧录时才制作额外视频；未实际预览时不宣称已验证最终画面显示。

## 分句与时间

语义分句由当前助手完成，脚本只清理和检查，不负责猜测语义或按字符数量分割。示例工作句：

“虽然这次带你们四个人去拍照，但下次带四个队友去踢球，车内空间也完全够用。”

可以分为依次显示的单行：

```text
这次带你们四人去拍照
下次带四个队友去踢球
车内空间也完全够用
```

每条必须定位其对应声音。优先使用原始字词时间戳；只拿到整句时间时需重新对齐或回听，不能按这三条文字长度均分时间。原本已有两行字幕时也必须回到来源文字和时间映射重新断句，不能把两行直接用空格粘成长行。

问句和回答逐发言分别显示。不能继续用上下两行同屏方式呈现两个人，也不能用对话破折号拼到同一行。连续发言时直接切换，上一条不能覆盖下一条。

### 默认连续显示

先核准切入及声音边界，再设置显示结束：**切入时间不变，上一条显示到下一条开始时再切换**。例如原来第一条10.0–12.0秒、第二条13.0秒切入，第一条改为10.0–13.0秒；SRT中边界相接，不人为再留一帧或一毫秒空白。

以下采用用户确认过的编辑预设，不是自动场景识别或行业标准：

- 两条之间停顿不超过2秒、延长后整条显示不超过7秒时，结束等于下一条开始。
- 停顿超过2秒或会显示超过7秒，保留本条输入的结束时间，不截短已有字幕。
- 最后一条保留输入的结束时间；已确认的转场或需清屏位置，在前一条加 `"hold_to_next": false`。
- 用户要求全程衔接或其他阈值时按其要求修改预设；明确要求保持现有结束时间时使用 `"display_policy": {"mode": "original"}`，它只禁用新的延长，不自动撤销已处理文件里的结束时间。

顶层可选配置为 `"display_policy": {"mode": "continuous", "max_gap_seconds": 2, "max_duration_seconds": 7}`。未提供时默认启用。逐条设置 `hold_to_next` 时必须为JSON布尔值。保留用户给定的声音边界/来源字段；脚本只延长显示结束，不改切入、文字、数量或原始 `speech_end` 等字段。延长条目增加 `display_original_end` 与 `display_hold_seconds`，逐条调整原因另存于 `display_adjustments`。

导出器先验证输入时间，零时长、越界、重叠不会被“补到下一条”掩盖。显示时长和阅读速度检查针对最终显示时间，不能据此宣称原文或声学同步已经准确。CLI自动保存同名 `.display.json` 作为内部记录。仅当用户明确要求试听或预览时才使用此文件生成视频，确保与SRT一致。

## JSON与调用

经校准和语义分句后保存：

```json
{
  "media_duration": 8.5,
  "subtitle_profile": {"layout": "portrait", "max_width": 14},
  "protected_terms": ["CX-5"],
  "cues": [
    {"start": 0.5, "end": 2.5, "text": "这款车驾驶起来很舒适。", "source_word_ids": [0,1,2]},
    {"start": 3.0, "end": 5.5, "text": "电量从30%充至80%。", "source_word_ids": [3,4,5]},
    {"start": 5.8, "end": 8.2, "text": "它的轴距是2.8米。", "source_word_ids": [6,7,8]}
  ]
}
```

以上时间和来源ID仅说明格式，真实任务必须从媒体取得，不能照搬。

```sh
python scripts/export_srt.py edited.json output.srt
# 使用探测生成的完整profile覆盖JSON内配置
python scripts/export_srt.py edited.json output.srt --profile profile.json
# 只有画幅选择时可以显式覆盖；会重置旧画幅/字体拟合信息
python scripts/export_srt.py edited.json output.srt --layout portrait
```

layout缺失会报错。输入有换行、残留明显粤语或清标点后超宽也会报错，输出前应修正分句和对应时间。导出器不自动折行、删内容或重定切入，仅按上述规则延长显示结束。速度、时长等警告须结合声音处理，无法满足的项目列待审，不声称已经验证。SRT或同名显示JSON已存在时拒绝覆盖，应换新输出名。

## 标点清理与保护

先保留标点做语义分析，完成分句和定位后才清理最终字幕。删除句读、引号、括号、省略号、对话破折号和一般装饰符号，必要处留下单个空格，绝不插入新行。保留小数、正负号、百分比、比例/时刻、数值范围与型号内部符号；千分位金额如1,000规范为1000，不能变成1 000。

| 工作文本 | 最终显示 |
|---|---|
| 这款车，驾驶起来不错！ | 这款车 驾驶起来不错 |
| 轴距为1.8米。 | 轴距为1.8米 |
| 电量为30%～80%。 | 电量为30%～80% |
| 温度低至-5℃。 | 温度低至-5℃ |
| CX-5的配置。 | CX-5的配置 |
| 0—100km/h加速。 | 0—100km/h加速 |

protected_terms只用于已核准正式名称/技术记号中特殊符号的保护，不能放整句、普通引号或句读绕过清理。无法确定符号是否属于名称时核对用户资料并记录疑点，而不是全删。无标点只应用于每个事件的正文；SRT时间轴中的冒号、逗号及箭头是文件格式，必须保留。
